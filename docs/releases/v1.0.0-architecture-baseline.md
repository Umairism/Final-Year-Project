# HealSense v1.0.0 Architecture Baseline

## Purpose

This release represents the frozen architectural state before migration to the direct cloud-native architecture.

## Current Architecture

* ESP32 / IoT sensor telemetry acquisition layer.
* Raspberry Pi 5 documented topology.
* FastAPI cloud backend framework.
* PostgreSQL relational persistence layer.
* Deterministic physiological safety rules engine.
* LSTM temporal evaluation model (60-second sliding windows).
* Hybrid decision fusion engine (Critical hard override + experimental weights).
* Gemini LLM natural language explanation layer.
* Web & Mobile monitoring dashboard.

## Known Limitations

* Raspberry Pi 5 exists only as documented architecture; no backend code depends on it.
* Direct ESP32 telemetry ingestion endpoint (`/api/v1/telemetry`) not yet implemented.
* Device authentication headers not enforced on vital ingestion paths.
* Blood Pressure acquisition source tracking (`bp_source`) unavailable.
* Offline ESP32 NVS local storage buffering and `delayed_sync` tagging unavailable.
* Cloud-native deployment manifests (`docker-compose.yml`) missing.

## Migration Target

Future versions will introduce:

* Direct ESP32 HTTPS telemetry ingestion.
* ESP32 NVS offline buffering with retry queues.
* Device API Key authentication.
* Nullable Blood Pressure schema with explicit missingness support.
* `delayed_sync` historical sync tracking.
* Dockerized cloud-native deployment.
