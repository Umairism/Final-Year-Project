# HealSense v1.1.0 Database Alignment Release

## Overview

This release completes Phase 1 of the HealSense cloud-native architecture transition by updating database models, Pydantic schemas, and Alembic migrations to support direct IoT telemetry acquisition, device authentication preparation, and explicit Blood Pressure metadata tracking.

---

## Key Schema Changes

### 1. `VitalSigns` & Telemetry Schema Enhancements
* **`bp_source`**: Added Enum field tracking Blood Pressure acquisition mechanism (`manual_entry`, `ble_cuff`, `hardware_uart`, `none`). Default value is `'none'`.
* **`delayed_sync`**: Added boolean flag (`DEFAULT FALSE`) indicating whether telemetry was ingested in real-time or sync-uploaded from ESP32 local Non-Volatile Storage (NVS) after a network reconnection.
* **Nullable Blood Pressure**: Refactored `CanonicalClinicalFeatureSchema` and `VitalSignsBase` to support optional/nullable `systolic_bp` and `diastolic_bp` without requiring synthetic default value imputations (`120/80 mmHg`).

### 2. `Device` Table Enhancements
* **`api_key_hash`**: Added nullable string column (`VARCHAR(128)`) to store hashed device secrets for direct HTTP header authentication (`X-Device-API-Key`).
